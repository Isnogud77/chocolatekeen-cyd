# Saving Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Autosave on returning to the world map, "Continue Game" resumes it, game over deletes it, high scores persist — on ESP32 NVS and host files.

**Architecture:** `CVort_engine_cross_rw_misc_fopen` (upstream/engine/engine_io.c, today NULL) becomes a "file on a blob" in platform-neutral `port/save_store.c`: reads are `fmemopen` over a loaded copy, writes are a FILE whose close callback commits to a backend store (`port_store_load/save/erase`). Upstream's save payload code (`CVort_private_read/write_saved_game_payload`, menus.c) and score code stay unchanged; small `// ESP32-PORT:` patches add autosave, direct continue and erase-on-game-over.

**Tech Stack:** C99, `funopen` (macOS) / `fopencookie` (newlib, ESP32), ESP32 NVS (`nvs_flash`/`nvs_*` or Arduino `Preferences`), Unity.

**Spec:** `docs/superpowers/specs/2026-11-05-saving-design.md`

## Global Constraints

- Store API: `int port_store_load(const char *name, uint8_t *buf, int max)` (bytes read, −1 if missing); `bool port_store_save(const char *name, const uint8_t *buf, int len)`; `void port_store_erase(const char *name)`. Names are upstream file names (`SAVEGAM1.CK1`, `SCORES.CK1`), ≤ 15 chars (NVS key limit).
- Max blob size 2048 bytes; the write buffer exists only while a write FILE is open.
- `"rb"` on a missing name → NULL. `"wb"` → nothing reaches the store before `fclose`. Other modes → NULL. Only `SAVEGAM1.CK1` and `SCORES.CK1` are served; `CTLPANEL.CK1` and demo files stay NULL.
- Autosave slot is `SAVEGAM1.CK1` (`CK_Path_FormatSavedSlot(path, size, '1', game_ext)`).
- ESP32: NVS namespace `keen`. Host: directory `~/.keen-esp32/` (created on first save).
- Write failure: log once, game continues. Corrupt save on load: treat as no save and erase it.
- Every upstream change carries `// ESP32-PORT: <reason>`.
- Heap at menu ≥ 30 KB on device.

## Review Focus

1. **Write FILE closed without commit** (upstream error paths that `fclose` after a failed payload write) → must still free the buffer; a short/failed write must not replace a good save. Task 1 test.
2. **Autosave after a death with lives left vs. game over** → save only when lives remain; game over erases. Task 3 tests.
3. **Continue with a save from a finished game or bad data** (levels array, map position out of range) → upstream's own load validation; treat failure as no save. Task 3 corrupt-save test.
4. **NVS commit not called / handle leak on ESP32** → each save opens, writes, commits, closes. Review.
5. **Name entry → score write → power loss** → scores must be in the store after the score screen. Task 4 host check, device check.
